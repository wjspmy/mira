## 1. 跨标签撤销历史隔离

### 状态

已修复，待持续回归。

### 修复记录

- `5366d50 Fix tab undo and scroll isolation`
- `e041d9f Fix tab-specific undo history`

### 当前判断

当前切换标签时会先保存离开标签的 Markdown 快照和滚动位置，再加载目标标签自己的 `rawMd`，并重建当前编辑器状态以清空 history。这样可以避免 `Ctrl+Z` 跨标签回退到上一个文件内容。

### 建议回归场景

1. 打开文件 A，编辑但不关闭。
2. 打开文件 B，编辑后按 `Ctrl+Z`。
3. 确认 B 只撤销自己的内容，不会变成 A 的内容。
4. 在同名文件、未命名文档、多标签快速切换场景下重复验证。

## 2. 外部资源管理器重命名/移动文件同步

### 状态

已实现基础修复，复杂文件系统事件仍需持续回归。

### 修复记录

- `e30f2cf Fix file move tab synchronization`

### 当前判断

Rust 端已经尝试识别 `notify` 的 `RenameMode::Both`、`RenameMode::Any`、`RenameMode::From` / `RenameMode::To`，并向前端发送：

```ts
fs:moved { oldPath, newPath }
```

前端收到 `fs:moved` 后会同步：

- 文件树缓存；
- 展开状态；
- 已打开 tab 的 `filePath`；
- 最近打开列表；
- 当前编辑器图片解析目录；
- 目标路径重复 tab 的合并。

同时，前端也对 Windows 上常见的 `delete + create` 组合事件做了短时间窗口内的兜底配对。

### 建议回归场景

1. 在资源管理器中重命名当前打开文件。
2. 在资源管理器中移动当前打开文件。
3. 在资源管理器中移动包含已打开文件的文件夹。
4. 目标路径已经存在打开 tab 时，确认不会出现重复或错乱。
5. 快速连续 rename/move，确认文件树、tab、最近打开同步正常。
6. 跨磁盘移动时，确认 `delete + create` 兜底表现可接受。

## 3. 窗口关闭 / 崩溃恢复对 dirty 文档保护不足

### 状态

部分解决。

### 已完成

当前已增加窗口关闭前 dirty 文档拦截：如果存在未保存文档，关闭窗口前会提示用户确认是否退出并丢弃修改；用户取消时会阻止窗口关闭。

### 仍未解决

应用崩溃、进程被强制结束或异常退出时，对未保存内容的保护还不完整。尤其是未命名文档或尚未自动保存完成的内容，仍存在丢失风险。

### 后续建议方案

1. 实现草稿恢复机制：
   - 定期保存未命名 / dirty 文档草稿；
   - 启动时检测未恢复草稿；
   - 提供恢复或丢弃选项。
2. 增加异常退出后的恢复提示。
3. 为窗口关闭、草稿恢复补充手动回归或 E2E 测试。

## 4. 文本编码 / BOM / 行尾策略未完成

### 状态

未解决。

### 现象

当前后端文本读取仍以 UTF-8 为基础，未实现完整的编码探测、BOM 处理、GBK 回退和行尾风格保留。

### 影响

Windows 中文用户打开历史 Markdown 或其他编辑器保存的文件时，可能遇到读取失败或保存后行尾/编码变化。

### 后续建议方案

1. 读取时探测 UTF-8 BOM / UTF-8 / GBK 等常见编码。
2. 保存时尽量保留原文件编码和行尾风格。
3. 在无法识别编码时给出明确提示，而不是静默破坏文件。

## 5. 文件系统命令路径沙箱未完成

### 状态

未解决。

### 现象

当前 Tauri 后端文件操作命令直接接收前端传入路径。虽然 Mira 是本地单用户桌面应用，但发布前仍应补齐路径边界校验。

### 后续建议方案

1. 维护允许访问的根路径集合，例如当前工作区根目录、用户显式打开的文件所在目录。
2. Rust 端对传入路径做 `canonicalize`。
3. 确认目标路径位于允许根集合内。
4. 对删除、移动、重命名、写入等高风险操作优先加校验。
