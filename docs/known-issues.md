## 1. 跨标签撤销历史隔离

### 状态

已修复并验收。

### 修复记录

- `5366d50 Fix tab undo and scroll isolation`
- `e041d9f Fix tab-specific undo history`

### 当前判断

当前切换标签时会先保存离开标签的 Markdown 快照和滚动位置，再加载目标标签自己的 `rawMd`，并重建当前编辑器状态以清空 history。这样可以避免 `Ctrl+Z` 跨标签回退到上一个文件内容。

### 已验收 / 发布前抽检场景

1. 打开文件 A，编辑但不关闭。
2. 打开文件 B，编辑后按 `Ctrl+Z`。
3. 确认 B 只撤销自己的内容，不会变成 A 的内容。
4. 在同名文件、未命名文档、多标签快速切换场景下重复验证。

## 2. 外部资源管理器重命名/移动文件同步

### 状态

已修复并验收。

### 修复记录

- `e30f2cf Fix file move tab synchronization`
- Task 7：抽取公共路径工具并补充路径归一化 / 前缀替换单元测试。
- Task 8：补充 workspace / recent / session store 级移动、去重、路径归一化回归测试。

### 当前判断

Rust 端已经尝试识别 `notify` 的 `RenameMode::Both`、`RenameMode::Any`、`RenameMode::From` / `RenameMode::To`，并向前端发送：

```ts
fs:moved { oldPath, newPath }
```

前端收到 `fs:moved` 后会同步：

- 文件树缓存；
- 展开状态；
- 已打开 tab 的 `filePath`；
- 最近打开列表；
- 当前编辑器图片解析目录；
- 目标路径重复 tab 的合并。

同时，前端也对 Windows 上常见的 `delete + create` 组合事件做了短时间窗口内的兜底配对。路径归一化、父子路径判断与移动前缀替换逻辑已抽到公共工具，并用 store 级测试覆盖工作区缓存、最近打开和会话快照，避免 App / store 多份实现漂移。

### 已验收 / 发布前抽检场景

1. 在资源管理器中重命名当前打开文件。
2. 在资源管理器中移动当前打开文件。
3. 在资源管理器中移动包含已打开文件的文件夹。
4. 目标路径已经存在打开 tab 时，确认不会出现重复或错乱。
5. 快速连续 rename/move，确认文件树、tab、最近打开同步正常。
6. 跨磁盘移动时，确认 `delete + create` 兜底表现可接受。

## 3. 窗口关闭 / 崩溃恢复对 dirty 文档保护不足

### 状态

已修复并验收。

### 修复记录

- Task 6：新增 dirty / 未命名文档草稿恢复。

### 当前判断

当前已增加窗口关闭前 dirty / 未命名文档拦截：如果存在未保存文档，关闭窗口或关闭 tab 前会提示用户确认是否丢弃修改；用户取消时会阻止关闭。

前端会将 dirty 文档和未命名文档的 Markdown 草稿保存到 `localStorage`，启动时检测未恢复草稿并逐个询问恢复或丢弃。正常保存、自动保存成功、关闭 tab 并确认丢弃、确认退出丢弃时会清理对应草稿，避免重复提示。

### 已验收 / 发布前抽检场景

1. 新建未命名文档，输入内容后强杀进程，重启后确认可恢复草稿。
2. 打开已有文件，编辑但不保存后强杀进程，重启后确认可恢复 dirty 内容。
3. 正常保存或自动保存成功后重启，确认不会继续提示旧草稿。
4. 关闭 dirty / 未命名 tab 并确认丢弃后重启，确认不会恢复已丢弃内容。
5. 关闭窗口时取消退出，确认文档内容与草稿仍保留。

## 5. 文件系统命令路径沙箱

### 状态

已修复并验收。

### 修复记录

- `f46da65 Enforce backend filesystem path sandbox`

### 当前判断

Tauri 后端文件系统命令已增加允许路径集合和规范化校验，前端显式打开的工作区 / 文件路径会被加入允许范围。后端返回给 UI 的路径也会去除 Windows extended-length 前缀，避免出现 `\?\C:\...` 这类内部路径泄漏到界面。

### 已验收 / 发布前抽检场景

1. 打开工作区后执行新建、重命名、移动、删除、保存，确认合法路径可用。
2. 打开工作区外的单文件，确认该文件及其相关资源目录可正常读写。
3. 验证 UI 中不再显示 `\?\C:\...` 形式路径。
4. 对工作区外未授权路径的直接文件命令应被拒绝。
